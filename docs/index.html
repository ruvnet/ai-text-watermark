01 · THE QUESTION

Where do you stamp a sentence?

From August 2026, the EU AI Act asks providers to mark AI-generated text. But a paragraph has no corner for a seal, and metadata dies on the first copy-paste. A visible tag ruins the writing; a hidden character is deleted by the first edit.

The mark has to live where edits can't reach and eyes can't see: inside the choices the model was already making.

02 · THE OPENING

Almost every word is a coin toss.

A model writes one word at a time, and at most steps several next words are equally good.

“…the weather is cold and overcast grey sugary”

overcast or grey — you'd never notice which landed. sugary was never in the running. The watermark only plays inside that harmless tie.

03 · THE TRICK

Swap the dice for the digits of π.

Normally the model settles a tie with a private roll of the dice — gone instantly. Watermarking keeps the odds identical but changes where the randomness comes from: a secret key plus the words just before decide the winner.

Like playing Monopoly with the digits of π instead of rolling — just as random, yet provable if you know π.

04 · THE PROOF

Reading the signature back.

Anyone with the key re-walks the text and asks at each tie: is this the word the key would have chosen? Human writing agrees by luck; watermarked writing agrees again and again — until coincidence is ruled out.

05 · THE LIMITS

What it honestly can't do.

Short or factual text carries almost no mark. “Newton's masterwork was the Principia…” has one right next word — no tie to hide in. Give the detector length.

A wrong key sees nothing. The mark holds no trace of you. It answers one question: was a keyed model likely involved?

And it is not a way to hide that AI was used. This toolkit only writes and checks marks — never strips them.

Three schemes. One line to switch.

◇

gumbel

Shifts the model's word-odds by zero. Provably distortion-free.

🔏 AI Text Watermark — docs

What this playground shows

Everything runs in your browser on the real @claude-flow/watermark WebAssembly core — no server, nothing leaves the page. The "tokens" are a synthetic stand-in for a language model's per-step candidate distribution, so you can watch generation and detection without wiring up a model. In production you feed the watermarker your model's real candidates (or logits, via the proxy).

The one idea

At most steps several next words are equally good. The watermark rides that tie — a secret key plus the preceding tokens decide which tied word wins, so the odds are unchanged but the choice is reproducible. A detector with the key re-walks the text and counts how often it matched; enough matches and coincidence is ruled out. Confidence grows with length and entropy (number of ties), which is why the sliders matter.

Reading the panels

Generation capabilities — throughput + how many positions actually carried the mark. Detection — four detectors, including a wrong-key row that reads ~0 (proving key-specificity) and an alarm threshold α you can move. Secret message — a hidden multi-bit payload (see below). Robustness — drag the edit slider and watch confidence hold, then fade.

const out = candidatesPerStep.map((c, i) => c[wm.step(c, probs[i])]);

Ultra-low-latency proxy (logits in → token out)

Drop StreamProxy into a decode loop: it takes raw logits (or a truncated top-k (ids, logprobs) set from an OpenAI-style API), applies temperature + top-k/top-p to match your sampler, and returns the watermarked token id — allocation-free after warmup.

const { StreamProxy } = require('@claude-flow/watermark');
const p = new StreamProxy({ key: 'my-secret', temperature: 0.9, topK: 40, topP: 0.95 });
for (const logits of decodeSteps) out.push(p.pushLogits(logits));

Secret message (multi-bit)

Each message bit is carried by which of two key-derived streams watermarks a block of tokens; extraction detects each block under both keys and takes the stronger. So the same text, read with the key, spells out a short payload (a model id, a run tag). Capacity trades off against robustness — roughly ~90 tokens per bit for a clean read.

Honest limits

Short or factual text carries almost no mark (few ties). A wrong key sees nothing, and the mark holds no information about you — it answers only "was a keyed model likely involved?". This toolkit only writes and checks marks — there is deliberately no removal / laundering tool.
