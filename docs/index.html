A field guide to text watermarking

The machine signs its work — and you'll never see the pen.

A watermark hidden not in the letters, but in the split-second choices behind them. Invisible to read. Undeniable with a key.

SCROLL
01 · THE QUESTION

Where do you stamp a sentence?

From August 2026, the EU AI Act asks providers to mark AI-generated text so it can be recognised later. But a paragraph is just words — no corner for a seal, no metadata a copy-paste won't strip. A visible tag ruins the writing; a hidden character dies on the first edit.

The mark has to live where edits can't reach and eyes can't see: inside the choices the model was already making.

02 · THE OPENING

Almost every word is a coin toss.

A model writes one word at a time, and at most steps several next words are equally good.

“…the weather is cold and overcast grey sugary”

overcast or grey — you'd never notice which landed, and the meaning is identical. sugary was never in the running. The watermark only plays inside that harmless tie — it never fishes out an odd word, so the writing is untouched.

03 · THE TRICK

Swap the dice for the digits of π.

Normally the model settles a tie with a private roll of the dice — pure chance, gone instantly. Watermarking keeps the odds identical but changes where the randomness comes from: a secret key plus the words just before decide the winner.

Picture Monopoly played by reading successive digits of π instead of rolling. Just as random — yet if you knew π, you could prove the game followed it.

04 · THE PROOF

Reading the signature back.

Later, anyone with the same key re-walks the text and asks at each tie: is this the word the key would have chosen? Human writing agrees now and then by luck. Watermarked writing agrees again and again — and coincidence runs out of excuses.

The detector tallies those agreements into a confidence that climbs with length.

05 · THE LIMITS

What it honestly can't do.

Short or factual text carries almost no mark. “Newton's masterwork was the Principia…” has one right next word — no tie to hide in. Same for most code and a light proofread. Give the detector length.

A wrong key sees nothing. The mark holds no trace of you — not your name, account, or conversation. It answers one question: was a keyed model likely involved?

And it is not a way to hide that AI was used. This toolkit only writes and checks marks. To get un-marked output of your own model, you don't apply the mark — you never strip a finished text.

06 · THREE FLAVOURS

Pick your trade-off.

One idea, three dials — from “don't disturb a single probability” to “sign as firmly as possible.”

gumbel

Shifts the model's word-odds by zero. The gentlest signature.

tournament

The SynthID method — a stronger mark for a whisper of bias.

tournament_nd

The middle path: unbiased on average, still firm.

Plus two specialist readers: one that keeps finding the mark after the text is edited and shuffled, and one that wrings confidence from a very short passage.

07 · IN YOUR HANDS

Ten lines. Nothing to compile.

It ships as a WebAssembly module — Node or the browser, no native build:

// npm install @claude-flow/watermark
const { Watermarker, detect } = require('@claude-flow/watermark');

const wm = new Watermarker({ key: 'my-secret', scheme: 'gumbel' });
const out = tokens.map(() => cand[wm.step(cand, probs)]);

const r = detect(out, { key: 'my-secret', scheme: 'gumbel' });
r.isWatermarked(1e-6);  // → true

Browser: import … from '@claude-flow/watermark/web' then await init().

Provenance, not surveillance — a mark that says “a machine helped here,” and nothing more.
